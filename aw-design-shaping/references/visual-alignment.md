# 可视化对齐

文字不足以表达页面组织、空间关系、步骤或交互时读取。

## 图要回答什么

每张图说明待定问题、当前方案和希望用户判断的内容。布局问题用低保真线框图；任务顺序用流程图或可点击步骤；业务规则用例子或决策表。概念和范围问题继续用文字。

## 会话内展示与降级

线框图、布局比较和低保真方案默认用当前宿主支持的 inline-html 直接嵌入会话，让用户当场查看和反馈。只生成文件、贴源码、给浏览器链接或截图都不算会话内展示。先核对宿主实际的内嵌能力与调用约定，不编造渲染语法；确认不支持时先说明限制，再降级为独立 HTML / 浏览器预览，并在简报记录降级方式。用户指定其他形式时沿用。

简单流程图可用 SVG 或 Mermaid。复杂多弹层确有需要时可借助 `aw-canvas-design`，它不是基础依赖。

## 保真度

低保真聚焦内容、结构与行为，用真实类型和合理长度的内容，不全是灰块。已有组件有助判断时复用，不为讨论布局搭完整工程。比较多个方案时使用相同任务、内容和相近保真度，标明每个方案改变了什么，不用视觉精致度引导选择。

## 反馈与迭代

每次只给当前判断所需的少量方案；用户文字纠正优先，浏览或点击不等于批准。静态稿注明覆盖的布局与状态；可交互稿让主要讨论动作有反馈，并说明哪些行为是模拟。只用本地隔离数据，不触发真实授权、提交或外部写入。修改方向时同步简报和图稿，旧方案标为已替代。

交付前在实际交付方式下渲染，检查文字、视口和主要交互；无法预览时报告未验证项。业务规则的认可与图稿的认可分别记录。
