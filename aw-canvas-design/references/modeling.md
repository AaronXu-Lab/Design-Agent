# 业务流程盘点与建模

仅流程模式的新流程、分支变化及覆盖审查时读取；收集对齐比较使用 [设计平铺](design-tiling.md)；纯样式或局部文案改动只核对对应行。

## 从入口追踪事实

从路由、列表/详情按钮及其他真实调用方追踪：入口条件 → 组件 → 状态判断 → 用户操作 → 结果/下一步。查 imports、动态加载、配置注册与 feature gate；搜索无引用只是线索，排除动态引用后才能记为不可达。旧代码单列并附证据，不自动删除。区分当前行为、用户要求的新设计和待核实项。

按业务能力选择正常、加载、待处理、无数据、不可用、失败、取消、重试等实际存在的状态。每种状态说明进入条件、可用操作、退出结果、身份/归属/选择等上下文是否保留。不能为凑齐清单制造重试、二维码、授权或错误恢复分支。

## 可维护的覆盖表

使用项目现有格式；没有时建立以下列的表格：

| 流程名（`preview`）、类型 / 所属主流程 / Section / 引用 | 场景 ID | 实际入口与条件 | 组件及源码证据 | 状态与能力依据 | 节点 ID / 新增·修改·复用 | 操作 → 边 ID → 结果 | 画布验证 | 实际入口验证 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

状态用通过、未验证、阻塞或不适用及理由，不能用画布成功填入入口成功。入口多对一时保留各调用方行或显式关联。未接入的新设计标记“提议/待迁移”，旧不可达代码另列，避免混入当前覆盖率。

## 流程目录归属（仅 flow）

Sidebar Section 分为“主流程”和“其他流程”（标签沿用项目国际化）。主流程按核心用户目标或连接路径聚合，不把每个授权阶段、复用步骤、条件组合或异常状态列成独立根项；业务域与主流程数量由当前需求决定。

| 类型 | 语义与归属证据 |
| --- | --- |
| 主流程 | 核心任务从入口到结果的完整路径；从属流程通过 `parent` 归入它 |
| 子流程 | 可复用、可被主画布引用并独立查看的步骤；记录调用/引用关系 |
| 分支流程 | 主流程在明确条件下的变体或组合；记录条件及所属主流程 |

步骤或状态不同不自动构成独立流程，仍可用同一节点的场景切换。其他流程只容纳有独立触发入口、无法归属某一主流程的补充任务或跨流程恢复任务；明显从属主流程的条目必须迁入其文件夹，不为分类方便放入其他组。独立补充任务可按完整任务路径建模，Section 表示任务分组，不另造第四种流程类型。

有子流程或分支流程的主流程与从属项打包为一个文件夹：首项保留主流程入口，其后是子流程和分支入口；没有从属项直接显示主入口，不造空文件夹。流程仍最多两级。`parent` 表示目录所有权，跨流程复用不改变它，也不复制整套画布；组合中的既有步骤通过引用节点的 `link` 指向已有流程。目录重组保留稳定 ID、URL、引用、独立预览与返回路径。图标及文件夹交互的事实源见 [flow 目录](canvas-presentation.md#flow-目录)。

这些规则只用于 flow；tiles 的 Dialog/Sheet 独立类型 Section Group → 业务模块平铺、无文件夹/折叠树规则保持不变。具体案例仅在 [目录回归案例](../tests/flow-directory.md) 说明，不作为通用业务清单。

## 图与组件的映射

UI 节点引用实际组件、场景参数及初始状态；入口、条件、结果节点可为说明卡。一个组件可由多个节点展示不同状态，同一场景 ID 保持稳定，位置与标题不作身份标识。每条可独立走通的流程注册一个稳定的 kebab-case 流程名，作为 `?preview={name}` 的值；改名视同新流程并更新引用。流程最多两级（顶层流程 › 子流程），以一个完整的业务段落为单位划分；流程复杂时允许子流程复杂一些，不为连线指标或字号继续拆分。同一页面的多种结果优先合成一个节点的场景切换，不拆成多个节点。新增/修改/复用相对本次任务基线判断，局部迭代不丢失变更语义。

边记录触发动作、守卫条件、结果和必要上下文，区分成功、取消/返回与重试；线型只是辅助，文字必须明确。建模时即标注每条边是“画线”（主路径、业务分支、终态结果）还是“出口”（有去向的返回、取消、关闭）；重新发送、刷新状态、联系管理员等页面内一眼能懂的原地操作不建边也不列出口，规则见 [连线精简](initialization.md#连线精简)。每条流程单独建模，跨流程复用同一展示组件时可各放一个场景节点；复用整段流程时用引用节点指向已有流程，不复制其整套画布；不连跨流程边。检查孤立节点、不存在的端点、重复 ID、无入口可达分支和无出口状态。并非所有终点都要回主流程，关闭可结束当前尝试。

画布内单节点交互可以局部模拟下一步，也可以联动流程；必须标明采用哪种方式，并使其可观察结果与边定义一致。不能把一条画出来的边当作按钮已接通的证据。

## 非连接器例子

批量导入业务可以按真实能力建模为：文件选择 → 字段映射 → 校验结果 → 提交结果；若现有实现只提供关闭错误提示，则不新增自动重试。加载与空数据节点只有在入口条件或需求有依据时才展示。评论绑定“字段映射/必填字段缺失”场景，避免绑到会变化的显示位置。
