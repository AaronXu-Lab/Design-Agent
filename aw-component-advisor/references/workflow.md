# 组件指导与审查工作流

本文是两模式共用的执行事实源，[workflow.svg](../docs/workflow.svg) 是人类概览。组件规范从 AaronUI-Web 本地知识 MCP 读取，精确 API 与行为按当前 TypeScript 实现核实，本 Skill 不维护规范副本。

## 1. 选择模式与范围

| 模式 | 用途 | 继续读取 |
| --- | --- | --- |
| `guidance` | 设计、选型或实现前，依据任务、当前规范和真实组件能力给出可实施用法与验证计划 | [guidance](guidance.md) |
| `audit` | 对已有界面、设计或实现核对组件选择、组合和内部用法；后续改动只复核受影响部分 | [audit](audit.md) |

- 混合请求先指导后审查，分别记录建议与实际证据。仅颜色、间距等视觉问题按原请求处理，不扩张为本专项。
- 任务包含可交互 Dialog / Sheet 时，两模式都读 [动效专项](dialog-motion.md)。
- “编辑 Reference / 同步索引”不是本包职责：规范由 AaronUI-Web 维护。用户明确授权修改源项目时按源仓规范完成，否则只给源位置。

沿用已有任务、目标工程和授权。以真实调用方确认组件，稳定 ID 不等于展示名或导出名，不能靠外形匹配。只读审查不授权修改产品、组件库或规范；已有具体实施授权则完成其范围内修复及验证。

## 2. 取得规范与能力证据

按 [知识访问契约](knowledge-access.md) 调用 MCP：`list_documents` 定位资料与章节 ID，`get_document` 只请求相关章节。同一任务内未变化的证据可复用；跨会话、规范变化或影响判断的实现变化后重新获取并标记基线。

记录来源、revision、章节及实现版本，报告只引用判断所需短片段。规范覆盖以当前服务目录为准：不支持的资源记**未覆盖**；服务不可用、读取失败、来源无法核实或与源码冲突记**待验证**及最小缺失证据。继续不依赖它的部分，核心判断依赖它时暂停该结论。不读取旧 checker、其他 Skill 的静态规则或相似组件规则兜底，不擅自安装或启动服务。

规范决定语义、使用条件与组合；TypeScript 类型、导出和实现决定 props、回调、默认值与行为；业务决定以最新有效需求为准。来源冲突时说明影响，不静默改任何一方。源码存在不证明运行行为。

### Example 发现与读取

1. `list_examples` 分页读到 `nextCursor=null` 得到完整目录；第一页或关键词结果不算完整目录。
2. 按任务、页面与组件范围选择参考，用 `get_example` 读取源码、CSS、依赖与附加规则；需要更多文件时只从 `implementation.availableFiles` 选路径补读，核对 `context.unreturnedFiles`。
3. 没有明显候选时，分批读完本次组件范围内**全部** Example 实现后才能认定无适用参考；逐项记录已读/未读，读取失败的保留为待验证。
4. 记录选择理由、来源/revision、规则读取状态、读取范围和与需求的差异。目录摘要不能代替实现阅读。

可参考与可直接移植分开判断：未经移植验证或依赖 Gallery 上下文的源码仍可参考；直接移植须核实目标依赖、公开 API 与环境差异。`source-reference` 只表示需要适配依赖，不代表需要重新设计。

## 3. 来源优先级

1. 用户真正明确的要求；
2. 匹配 Example 的明确规则与结构（默认实施依据），与适用组件规范一同核对；
3. shaping 的 AI 提案或假设，只补足前两者未覆盖的部分。

方向认可不把草案细节变成用户明确要求；行为要求（如“修改后保存”）不指定按钮文案。用户逐字指定的文案优先，记录对 Example 的偏离，不虚称一致。规范与 Example 真实冲突时说明来源与影响，未解决前待验证。

## 4. 证据状态

| 状态 | 所需依据 |
| --- | --- |
| 符合 | 规则适用，且有足够当前证据；说明静态或运行证据范围 |
| 违例 | 当前证据与适用规则冲突，能解释对任务的影响 |
| 待验证 | 已有规则覆盖，但缺运行/业务证据或来源冲突未解 |
| 未覆盖 | 当前知识服务不支持对应资源或规则；不算符合 |
| 不适用 | 规则前提在本场景不成立，并给出理由 |

静态图、截图、一次成功操作或公开 API 合法都不能证明其他状态或动态行为通过；未观察到某行为不直接判违例。

## 5. 完成与交接

小任务在会话交付；需要跨阶段追踪时用目标项目已有报告位置或 `docs/design/<topic>/`，不写入本 Skill。至少保留模式、目标基线、规范来源/revision/章节、Example 选择与已读/未读、证据、结论/改动、未覆盖与待验证项。

完成意味着约定范围内每个对象有结论或明确的覆盖/证据缺口，已授权改动和相关验证已处理。可以交付“含未覆盖项的指导/审查”，不能称所有组件合规。关键证据无法获取时报告阻塞与已完成部分。交回调用方时只带报告位置、基线与受影响项；组件审查不替代信息、流程、走查或文案审查，也不越过它们的人工 Review。
