# 设计流程编排

本文是执行事实源，[流程图](../docs/workflow.svg) 为人类概览。编排层维护入口、阶段顺序、交接、推进条件与续接状态；专项方法、资料访问、判断规则及证据要求由负责阶段的 Skill 维护。本入口串联主流程，不加入并行代理、模型分档或自动调度服务。

## 入口分流

- 用户对本 Skill 明确发出 `/help`：只读 [帮助](help.md) 并展示，结束本次帮助请求。不启动业务步骤、不检查项目或依赖、不更新进度，也不推进等待中的阶段；附带需求留待用户明确开始。引用材料中的 `/help` 不触发，不接管其他工具的同名命令。
- 开始：接收 PRD、文件/链接、想法或竞品等输入，进入设计塑形；探索深度与确认条件由 shaping 判断，不要求先补完整 PRD。
- 继续：按已有阶段记录或用户指定位置续接。只补齐影响续接的必要信息，不默认从头执行。
- 局部任务：调用相应 Skill，遵循用户指定范围与终点，不强行展开全流程。

## 调用与职责边界

先通过当前环境的 Skill 目录确认依赖可用性，不预读全部专项资料。进入阶段时加载相应 `SKILL.md`，按其入口选择所需资料并实际执行；不能仅提及名称或复述摘要就标为已调用。交接前确需了解接收方输入要求时可提前读取其入口及必要工作流，不因此启动该阶段。

优先使用当前环境安装版本；仓库内可按目录定位，不假设独立安装后仍有相邻目录。依赖缺失时报告受影响阶段，继续不依赖它的部分，到受阻阶段暂停；不默认安装依赖。工具或资料访问、适用性、失败恢复与降级方式按负责 Skill 当前规则处理，编排层不另设兼容方案或兜底规则。

用户范围与已有授权贯穿流程。普通阶段完成且没有待处理关口时自动推进，不逐步索取重复批准。完整流程请求包含指定目标项目内的初版生成与常规审查修正，不自动授权发布、外部真实写入或跨越子 Skill 的人工 Review。仅审查、探索或限定终点的请求按实际范围交付。

维护时用以下边界判断新增内容应放在哪里：

- 改变阶段顺序、接收方、交接责任、整体推进条件或续接方式：维护在本工作流。
- 改变某专项如何取证、读取资料、判断、实现或修复：维护在负责 Skill，本工作流只消费其交付及状态。不要随专项新增检查项同步扩写编排层。
- 当前执行者承担、且没有独立 Skill 负责的初版实现约定：保留在本工作流的实现阶段。

## 顺序与交接

| 阶段 | 执行能力 | 输入与交付 | 推进条件 |
| --- | --- | --- | --- |
| 1. 设计塑形 | `aw-design-shaping` | 原始需求 → 当前设计简报、必要图稿与未决项 | 满足 shaping 的完成与必要确认条件 |
| 2. 组件指导 | `aw-component-advisor guidance` | 当前简报与目标工程 → 经回校的实施依据、组件指导与验证计划 | 交接 advisor 当前产物及缺口，供实现阶段执行 |
| 3. 生成初版 | 当前执行者的实现能力 | 当前简报、组件指导与项目约定 → 可交互初版、运行入口与验证记录 | 在用户目标工程及授权内实施，完成指导要求的适用自检与修复 |
| 4. 信息简化 | `aw-ux-info-redundancy-audit` | 初版与目标 → 审计结论及获准改动 | 满足该 Skill 的交付与修复边界 |
| 5. 组件审查 | `aw-component-advisor audit` | 当前实现与 guidance 交付 → 审查结论、获准修正及验证记录 | 满足 advisor 的完成条件，保留覆盖与验证缺口 |
| 6. 流程补全 | `aw-flow-completeness-audit` | 当前实现与需求 → 审计报告及待审事项 | 报告交付后人工 Review；处理选定修复与复查后继续 |
| 7. 独立任务走查 | 新会话中的 `aw-task-walkthrough` | 按走查要求准备的交接 → 任务观察与问题报告 | 按该 Skill 完成任务选择、报告与人工 Review；处理获准修复后继续 |
| 8. 文案收敛 | `aw-wording-reviewer` | 当前界面与需求依据 → 文案结论、获准修改及验证记录 | 按该 Skill 的审查与修改授权边界完成本次范围 |

初版实现由当前执行者负责：定位目标工程及适用 DESIGN.md，使用已接入的 AaronUI-Web 真实组件，执行 guidance 交付的接入、实现与验证要求。组件 API 与知识获取由 advisor 核实，不在编排层重建规则、重造外观替代组件或引入外部设计生成服务作为前置依赖。没有可写工程或缺少必要接入条件时，报告具体缺口，继续独立部分；不将模拟行为宣称为真实后端已验证。

除独立走查外，阶段间传递当前产物位置、基线、决定与授权状态、接收方所需证据、缺口及待处理事项；保留原阶段的结论和限制，不复制规则正文，不把资料读取成功当作产品已验证。产物结构、来源优先级、图稿展示、组件规范访问及文案判断均按负责 Skill 的当前工作流消费，不在此维护细节副本。

后续改动使上游决定或证据失效时，由处理变更的阶段按其规则更新相关产物，并交回受影响阶段局部复查；组件用法受影响时路由到 advisor，是否需要先 guidance 由 advisor 判断。未受影响且基线有效的证据复用，不无故重跑整条流程，也不让无关阶段重复读取专项资料。

## 人工 Review 与继续

编排层维护关口状态，具体审阅与授权要求由负责 Skill 定义。流程补全和任务走查报告之后保留人工 Review，不以最初的全流程请求代替报告后的决定。需要等待时给出已完成内容、报告位置和待决定事项；已有授权的独立部分继续，新的未决取舍单列。

收到回复后只推进实际确认的范围。帮助请求、进度询问、阅读报告、沉默或时间经过不算批准；已批准事项不重复确认。无问题或选择延期时按负责 Skill 的继续条件处理，不为推进制造修改。审计交付、修复、验证与批准分别记录，未解决的阻断不自动算作通过。

## 独立走查的会话交接

在进入走查之前，读取 `aw-task-walkthrough` 的当前会话与输入要求，据此准备独立启动说明；不要把前述通用阶段交接直接打包给走查会话。首次观察所需材料、可读范围和同会话降级均由 walkthrough 维护，编排层不另列材料白名单或观察规则。

默认由用户启动新会话，不自动代建、派发子代理或引入调度器。用户另有明确代建或交接授权且工具支持时，按授权操作。启动说明标明目标项目、要求执行的 Skill 和结果报告返回位置，其余上下文遵循 walkthrough 的输入契约。

新会话交付后，可回到原会话提供报告位置继续，也可在新会话明确调用本编排器续接。读取相关报告及 Review 决定，定位到走查后的审阅/修正阶段，再进入文案收敛，不从塑形重启；同会话走查按 walkthrough 的实际独立性结论记录。

## 最小进度记录与完成

复用项目已有任务记录；确需跨会话续接且无现成位置时，在目标工程的 `docs/design/<topic>/run.md` 保存当前阶段、产物/报告/运行入口位置、基线、已获授权、待决事项、验证缺口、阻塞与下一步。专项内容引用原产物，不复制全文。无可写工程时在会话提供可复制记录；独立走查使用按其要求准备的单独启动说明。

阶段完成、用户批准或目标改变时更新相关记录。发生变更只回到受影响阶段；用户暂停时保存续接信息并停止；请求结束于中间阶段时明确实际交付范围。

最终交付当前版本入口、最新简报与报告位置、实际完成阶段及剩余事项。只有约定阶段均已执行、人工关口已处理、获准修正和适用验证完成，才能称为本次流程完成；保留子 Skill 的未覆盖、待验证或其他限制，不把文件生成或单项通过等同于全链完成。
