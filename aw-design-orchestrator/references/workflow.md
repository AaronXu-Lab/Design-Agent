# 设计流程编排

本文是执行事实源，[流程图](../docs/workflow.svg) 为人类概览。编排层维护入口、阶段顺序、交接、推进条件与续接状态；专项方法、资料访问、判断规则及证据要求由负责阶段的 Skill 维护。本入口串联主流程，不加入并行代理、模型分档或自动调度。

## 入口分流

- **`/help`**：用户对本 Skill 明确发出时，只读 [帮助](help.md) 并展示后结束；不检查项目、不更新进度、不推进等待中的阶段。引用材料中的 `/help` 不触发。
- **开始**：接收 PRD、文件/链接、想法或竞品，进入设计塑形；不要求先补完整 PRD。
- **继续**：按已有阶段记录或用户指定位置续接，只补齐影响续接的信息，不从头执行。
- **局部任务**：直接调用相应 Skill，遵循用户指定范围与终点，不展开全流程。

## 调用与授权

先确认依赖 Skill 在当前环境可用，不预读全部专项资料。进入阶段时加载其 `SKILL.md` 并实际执行；仅提及名称或复述摘要不算已调用。依赖缺失时报告受影响阶段，继续不依赖它的部分，到受阻阶段暂停；不默认安装。

普通阶段完成且没有待处理关口时自动推进，不逐步索取重复批准。完整流程请求包含目标项目内的初版生成与常规审查修正，不包含发布、外部真实写入或子 Skill 的人工 Review。

## 顺序与交接

| 阶段 | 执行能力 | 输入与交付 | 推进条件 |
| --- | --- | --- | --- |
| 1. 设计塑形 | `aw-design-shaping` | 原始需求 → 设计简报、必要图稿与未决项 | 满足 shaping 的完成与确认条件 |
| 2. 组件指导 | `aw-component-advisor guidance` | 简报与目标工程 → 回校后的实施依据、组件指导与验证计划 | 交接 advisor 产物及缺口 |
| 3. 生成初版 | 当前执行者 | 简报、组件指导与项目约定 → 可交互初版、运行入口与验证记录 | 在目标工程及授权内实施，完成指导要求的自检与修复 |
| 4. 信息简化 | `aw-ux-info-redundancy-audit` | 初版与目标 → 审计结论及获准改动 | 满足该 Skill 的交付与修复边界 |
| 5. 组件审查 | `aw-component-advisor audit` | 当前实现与 guidance 交付 → 审查结论、获准修正及验证记录 | 满足 advisor 完成条件，保留覆盖与验证缺口 |
| 6. 流程补全 | `aw-flow-completeness-audit` | 当前实现与需求 → 审计报告及待审事项 | **人工 Review** 后处理选定修复与复查 |
| 7. 独立任务走查 | 新会话中的 `aw-task-walkthrough` | 独立启动说明 → 任务观察与问题报告 | **人工 Review** 后处理获准修复 |
| 8. 文案收敛 | `aw-wording-reviewer` | 当前界面与需求 → 文案结论、获准修改及验证记录 | 按该 Skill 的授权边界完成 |

**初版实现**由当前执行者负责：定位目标工程及适用 DESIGN.md，使用已接入的 AaronUI-Web 真实组件，执行 guidance 交付的接入与验证要求；不重造外观替代组件，不引入外部设计生成服务。没有可写工程或缺少接入条件时报告缺口，继续独立部分；模拟行为不宣称为真实后端已验证。

阶段间传递：产物位置、基线、决定与授权状态、接收方所需证据、缺口与待处理事项。只传结论与位置，不复制规则正文。

## 变更回流

后续改动使上游决定或证据失效时，只回到受影响阶段局部复查，未受影响的有效证据复用：

- 任一阶段的获准修改改变 AaronUI-Web 组件选择、组合、内容或操作语义时，交 `aw-component-advisor` 局部复核（是否先 guidance 由 advisor 判断）；纯文字或流程状态变化不触发。
- 获准修改改变范围、主路径或关键规则时，由处理该变更的阶段按 shaping 的简报规则更新简报与受影响图稿。

## 人工 Review

流程补全和任务走查的报告之后保留人工 Review，最初的全流程请求不能代替报告后的决定。等待时给出已完成内容、报告位置和待决定事项；已有授权的独立部分继续。帮助请求、进度询问、阅读报告、沉默或时间经过都不算批准；已批准事项不重复确认。审计交付、修复、验证与批准分别记录，未解决的阻断不算通过。

## 独立走查交接

进入走查前读取 `aw-task-walkthrough` 的会话与输入要求，据此准备启动说明，标明目标项目、要执行的 Skill 和报告返回位置；不把通用阶段交接直接打包给走查会话。默认由用户启动新会话；用户另有明确授权且工具支持时才代建。

报告返回后（回到原会话，或在新会话调用本编排器续接），读取报告及 Review 决定，从走查后的审阅/修正继续，再进入文案收敛，不从塑形重启。

## 进度记录与完成

复用项目已有任务记录；需要跨会话续接且无现成位置时，在目标工程 `docs/design/<topic>/run.md` 保存当前阶段、产物与报告位置、基线、已获授权、待决事项、验证缺口、阻塞与下一步，专项内容只引用。无可写工程时在会话提供可复制记录。阶段完成、用户批准或目标改变时更新；用户暂停时保存续接信息并停止。

最终交付当前版本入口、最新简报与报告位置、实际完成阶段及剩余事项。只有约定阶段均已执行、人工关口已处理、获准修正和适用验证完成，才称本次流程完成；保留子 Skill 的未覆盖与待验证项。
