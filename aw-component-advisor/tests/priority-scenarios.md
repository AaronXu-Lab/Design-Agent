# 来源优先级走查

维护三阶段交接或规则消费契约时使用。下列规则是测试夹具，不是生产规范或 Example 名单；执行真实任务时读取当前源。检查决定、来源归属、简报回校与等待边界，不用关键词匹配代替行为判断。

| 输入与证据 | 应有决定与交接 | 不应出现 |
| --- | --- | --- |
| 用户要求“修改后保存”；AI 简报写确认按钮“保存”；匹配样例的当前明确规则要求 Rename / Cancel | 保留保存行为，采用 Rename / Cancel；把“保存”标成被替代的 AI 文案提案，注明规则来源、版本和适用范围；直接继续 | 宣称“保存”为用户指定，或为纠正草案新增审批 |
| 用户明确要求“确认按钮逐字显示‘保存’”；匹配样例规则要求 Rename | 用户明确要求优先；记录用户原话、规则来源及偏离，不声称符合该规则 | 静默改为 Rename，或把差异记成无冲突 |
| 用户认可整体方向；草案包含未讨论的操作文案；随后取得匹配规则 | 方向认可只证明方向；回校未明确指定的 AI 细节 | 将整份简报提升为用户逐字要求 |
| 任务简单明确，已有实施授权，Example 完整匹配 | 简短方向交接 → guidance 回校 → 实施；保留后续流程补全/走查的人工 Review | 强制探索方式选择、简报模板审批，或跳过必要 Review |
| 服务明确返回无附加规则，独立组件规范可读 | 按现有规范与匹配结构实施，AI 仅补足未覆盖细节；记录无附加规则的来源证据 | 宣称所有规范均不存在 |
| 服务返回 `not-declared`，没有规则绑定 | 记录规则覆盖缺口；不能证明无规则，也不把独立规范标成未覆盖 | 当作显式 `none` 或声称已完成全部规则核对 |
| 父 Example 返回多个子场景的规则，而当前任务仅匹配其中一个子场景 | 依据每项 scope 选取当前规则及适用的父级通用规则 | 把相邻子场景规则扩大到全部任务 |
| 旧响应没有规则字段、规则文件读取失败或版本不明 | 标记规则待验证，继续独立部分；依赖该规则的判断保持未完成 | 当作无规则、使用 AI 草案制造合规结论 |
| 无明显候选且组件范围尚未读完 | 分页读完目录，分批读完范围内实现；记录未读项 | 仅凭搜索无结果就宣称无适用 Example |
| Example 规则与适用组件规范冲突 | 记录双方来源与影响，待验证冲突；仅实际未决产品取舍交给用户 | 静默选一方并宣称全部合规 |
| 后续文案阶段恢复了已被规则替代的 AI 文案 | 对受影响组件局部 audit，按当前用户要求和规则重新核对 | 因前序曾批准方向就免除核对 |

本次维护自走查：以上十一种情境均能由工作流的依据顺序、回校要求与证据状态得出预期处理。此记录是文档语义自检，不是独立模型回放、产品运行测试或真实 MCP 响应验证。
