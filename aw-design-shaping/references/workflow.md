# 设计塑形工作流

将 PRD、模糊想法、竞品或它们的组合，转成用户认可的设计简报。本文是唯一执行工作流，[流程图](../docs/workflow.svg) 是面向人的概览。

塑形指明目标、范围与主路径，不是组件细节、结构或操作文案的最高依据。分别标注四类内容：用户明确要求、观察事实、AI 推断与提案、待定选择。行为要求与界面措辞分开记录：“修改后保存”规定结果，不等于指定按钮文案；方向认可也不把 AI 拟定的细节变成用户要求。

## 1. 建立当前理解

读取用户材料及与目标相关的项目现状，提炼目标用户、场景、期望结果、约束与本次范围。材料已能回答的不重复问；文档完整不代表其中假设已确认。组件库与 DESIGN.md 只作现实约束，塑形阶段不逐项选组件或做视觉规格；只有某项组件能力或 Example 会影响主方案时，才请求 `aw-component-advisor guidance`。矛盾影响主方案时指出具体冲突。

仅当探索方式会实质影响方向且尚未明确时，在开始时询问一次：

- 已有功能优化：推荐沿用现有结构与组件，针对有依据的问题调整。
- 新功能或重新设计：推荐先探索任务与结构，再核对落地代价。

简单明确任务直接提炼简短方向并交接，不为探索方式、简报格式或 AI 局部提案新增确认关口。

## 2. 按决策依赖追问

先处理会改变目标、范围、主要任务、页面职责或关键规则的决定；依赖未定答案的问题留到下一轮。每轮以用户能轻松回答为尺度，不一次倾倒所有问题。每个实质问题给出具体场景、选项影响和有依据的推荐。

- AI 主动查找可获得的事实，不把检索转交用户。
- 目标、范围、主路径和代价明显的取舍由用户决定；局部组织和表达由 AI 先提出。
- 可以挑战既定假设，但须说明场景、冲突或代价并给替代方向；用户理解取舍后的决定应被尊重。

用户改变目标或前置决定时，标记受影响的后续选择和图稿已失效，保留已确认的独立决定。

## 3. 选择探索手段

追问、竞品研究、方案比较和可视化按需交替，没有固定顺序。

| 当前不确定性 | 行动 |
| --- | --- |
| 谁遇到什么问题、成功意味着什么 | 具体场景、反例与聚焦追问 |
| 同类产品如何组织任务 | [竞品研究](competitor-research.md) |
| 同一目标有实质不同的解法 | 少量有意义的方案，比较用户成本与约束 |
| 页面职责、区域关系或步骤难以口述 | [可视化对齐](visual-alignment.md) |
| 某个规则会改变主结构 | 业务例子或决策表 |
| 当前系统能否支持影响方向的能力 | 聚焦只读查证或隔离的可行性探查 |

明显可行的方向不必凑三个方案；有真实分歧时不只呈现 AI 偏好。探索原型只用本地隔离数据，不连接真实写入。

## 4. 形成并比较方案

需求说明要达到的结果或约束，方案说明任务如何组织、在哪里操作、如何得到结果，不把需求换个标题当方案。从真实场景明确：主要业务对象、任务起点、页面或区域职责、主要操作顺序、可观察的完成结果，以及影响主路径的关键分支。其余异常状态留给后续流程完整性审查，不在此穷举。

多个方向时用关键需求对照，必要时用小表标「满足 / 不满足 / 待验证」。用户仍不认可时追问遗漏的场景或取舍，不替用户新增强制需求。选定或修改方向后同步简报、图稿与决定，旧方案标为已替代。

## 5. 收敛与确认

内容足以生成初版时，呈现与规模相称的方案摘要：面向谁、解决什么、包含与不包含什么；主要任务、页面职责、关键路径与完成结果；改变主方案的规则和取舍；剩余假设与证据缺口。只有尚未决定且会改变主方案的取舍才请用户确认；用户已认可完整方向时直接沿用。

用户提前结束或暂时无法回答时，保存进度与下一个待决问题，标为「探索中」，不伪称完成，不模拟同意。

## 6. 交付设计简报

复用项目已有设计文档位置；没有约定时保存为目标项目的 `docs/design/<topic>/brief.md`，图稿放同目录。没有可写项目时在会话交付完整简报并说明未落盘；不把业务资料存进本 Skill。

简报按需包含，简单任务合并成短段落：

- 目标、场景、成功结果与范围；
- 选定方向、任务路径与页面/区域职责；
- 影响初版的关键规则、已有设计约束及探索方式；
- 图稿位置、表达范围、版本与验证状态（降级方式见 [可视化对齐](visual-alignment.md)）；
- 关键决定与理由，重要参考的来源及采用/不采用原因；
- 暂用假设、未验证能力与后续检查事项。

让接手的新会话不读聊天也能继续。简报是持续更新的方向与来源记录：后续经批准改变范围、主路径或关键规则时，同步受影响的简报与图稿，简记新决定、依据、被替代内容和“已确认待实施 / 已实施”状态；未批准的建议保留为提案；项目已有事实源优先，简报引用而不复制。

交付前检查：主路径可解释、关键分歧已处理、来源与推断分明、图文一致。报告已确认内容、文件位置和剩余问题。本 Skill 不改正式业务代码；同一请求已授权后续实施时按授权继续，不制造重复确认。
