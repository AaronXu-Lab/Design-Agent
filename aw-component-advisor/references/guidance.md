# guidance：从任务得到可实施用法

先完成 [共用工作流](workflow.md) 的取证与 Example 选择。

## 映射与回校

按规范相关章节核对任务是否适用、与其他表面的边界、组合和内部内容职责。需要替代方案但没有规范支持时，给出任务层面的选择条件并标记未覆盖，不虚构其他组件的规则或能力。

把适用规则映射到目标场景：需要哪些信息与操作、各自服务哪个决定、如何进入与结束、哪些能力由调用方实现。核实 Example 适用范围后，默认沿用匹配 Example 的明确规则、结构与组件组合。

按 [来源优先级](workflow.md#3-来源优先级) 回校设计简报：标清每项影响决定的来源（用户原意 / 规范或 Example 来源与版本 / AI 提案），修正被规则替代的 AI 内容并记录差异。证据足以校正时直接更新并继续，不为简单任务新增批准关口；只有未决且影响主方案的产品取舍交给用户。

## 实施要求

当前执行者使用 AaronUI-Web 真实导出实现：定位目标项目的包依赖与引用方式，核实所需 props、事件与依赖组件；不凭规范名称猜 API，不重造外观相似的组件，不引入外部设计生成服务。目标工程未接入组件库时说明缺口，继续可独立完成的指导；接入依赖或跨仓修改沿用实际授权。

## 交付

与任务规模相称：场景与组件映射及理由、规范来源/章节、真实 API 依据、参考 Example 的选择与采用/调整/不采用部分、已读与未读项、调用方责任、必要状态与验证计划（含适用的 [动效专项](dialog-motion.md)）、未覆盖与待验证项。

指导完成不等于已实现。只要求指导时到此交付；已授权实现时继续实现，初版完成后立即执行验证计划中的自检，再以当前产物进入 [audit](audit.md)。
