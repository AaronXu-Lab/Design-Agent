# audit：从现有证据得到判断

先完成 [共用工作流](workflow.md) 的取证；同一任务中 guidance 的有效阅读记录可复用，但不替代本次源码与交互取证。

## 检查

按当前规范检查适用语义、场景边界、组合、内部用法和文案；维度来自取得的正文，不另建规则清单。针对相关入口和状态，分别以源码、可见设计和实际交互取证，不为局部审查运行无关全量检查。

按 guidance 记录的来源区分复核简报和实现，防止 AI 提案再次覆盖已匹配规则，并检查附加规则的适用范围。

## 与匹配 Example 对照

逐项记录本次适用的 variant、尺寸、排版、间距、状态与交互的对照事实与差异；维度随任务和 Example 确定，不扩展成固定清单。公开 API 合法只证明支持该用法，不证明符合 Example，也不足以支持偏离。实现或修复完成后对照原 Example 的实际渲染，无差异也留下双方基线与对照证据；无法对照时待验证。

每个差异给出处理结论：

- 按匹配 Example 对齐；
- 依据用户明确要求或有效业务规则保留，引用依据与影响（保留差异不等于符合被偏离的规则）；
- 证据不足则待验证。

Example 的演示简化逻辑不能覆盖有效业务规则，也不能以对齐为由删除业务约束。

## 结论与修复

每项结论写明位置、观察事实、适用规范章节、参考来源与差异、[证据状态](workflow.md#4-证据状态) 及影响；违例给最小调整建议。涉及可交互 Dialog / Sheet 时按 [动效专项](dialog-motion.md) 检查。

纯审查只交付结论。已授权修复时只处理选定范围，验证受影响的入口、状态和 API 使用，分别记录建议、已修改和已验证。规范变更影响既有结论时重读相关章节局部复核，不重跑整个流程。
